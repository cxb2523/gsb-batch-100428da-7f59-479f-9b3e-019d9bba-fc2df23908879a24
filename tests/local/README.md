# 本地离线验证（不依赖外部网络 / 真实站点）

这套验证用本机 Chrome/Edge 的无头模式，配合一个只监听 `127.0.0.1` 的静态服务器，
验证 `index.html` 的解密还原与**容错脚本执行链**。全程不访问任何外部地址。

## 运行

```bash
node tests/local/run-tests.js
```

脚本会自动：

1. 用与 `index.html` **完全相同的 XOR+base64 算法**把自造内嵌页加密进 7 个
   `gqsyljpsnak*` 隐藏输入框，生成测试夹具（`fixtures/`，已 gitignore）；
2. 在 `127.0.0.1` 随机端口起静态服务器（缺失脚本返回 404，模拟加载失败）；
3. 依次用无头浏览器加载各夹具，断言状态区的计数、逐条结局、首个失败原因、最终结局，
   以及“执行过程中持续更新”的中途快照；
4. 最后经本地 HTTP 加载仓库里真实的 `index.html`，确认原始载荷仍为“全部成功”。

## 覆盖的结局

| 夹具 | 场景 | 预期最终结局 |
| --- | --- | --- |
| `partial-failure.html` | 成功 → 内联执行异常 → 成功 | 部分失败，链不中断 |
| `load-failure.html` | 外部脚本 404 → 正常外部脚本 → 内联 | 部分失败，后续照跑 |
| `all-failed.html` | 两个内联脚本都抛错 | 全部失败 |
| `skipped.html` | JSON-LD/JSON 数据块、空 src、空内联、正常内联 | 全部成功，跳过被记录 |

每个夹具还带一个探针（`all-failed` 除外），在整个执行过程中以固定间隔把
`window.__psbRunner.state` 的计数快照写入 DOM，用来证明状态区是**实时持续更新**，
而不是结束时一次性写入。

## 文件说明

- `generate-fixtures.js` — 夹具加密生成器（密钥/算法与 `index.html` 一致）
- `server.js` — 仅监听 `127.0.0.1` 的静态服务器（`/` 为夹具，`/repo/` 为仓库根）
- `run-tests.js` — 无头浏览器驱动与全部断言

## 说明：为什么无头预算设为 4 秒

原始内嵌页自带 5 秒倒计时跳转。无头 `--virtual-time-budget` 一旦超过 5 秒就会触发
跳转并让 `--dump-dom` 挂起，因此测试统一用 4000ms 预算，确保采集链在跳转前结算完毕。
真实浏览器中状态区会照常实时更新，跳转行为也不受影响。
